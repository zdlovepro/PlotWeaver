# 作者 Skill 评测与验收规范

**状态：** 目标规范；当前系统已实现部分结构保真评测，作者级盲测尚待实现

## 1. 基本原则

评测必须回答“哪里出了问题”，而不只返回一个总分。不得由同一个写作模型在看过原文后给自己的文本打一个分，便宣布Skill成功。

完整评测由六个彼此独立的层次组成：

```text
来源文本 → 标注 → 图谱 → 章节程序 → 生成正文 → 作者Skill效果
```

前一层失败时，后一层分数只能用于诊断，不能覆盖前一层硬错误。

## 2. 评测数据集

| 数据集 | 用途 | 是否可调参 |
|---|---|---:|
| 训练集 | 提取模板、统计风格、可选SFT/LoRA | 是 |
| 开发集 | 调提示词、阈值、检索预算、候选权重 | 是 |
| 章节盲测集 | 检验事件和写法还原 | 否 |
| 作品盲测集 | 检验作者核心跨作品泛化 | 否 |
| 原创连续生成集 | 检验新人物、新设定下的可用性 | 否 |
| 同题材对照集 | 检验作者辨识度而非题材辨识度 | 只用于训练判别器时须另留测试集 |

盲测样本一旦被用于修改规则，就转为开发集，并补充新的盲测样本。

## 3. 标注与图谱评测

随机抽取至少5章，逐条检查：

- 实体是否合并正确；
- 事实是否有原文证据；
- 事件是否包含正确的行动者、动作和结果；
- 稳定关系是否被一次性交互污染；
- 人物位置、资源、能力、目标和知识状态是否正确迁移；
- 因果边是否真的是原因或前置条件；
- 时间空间关系是否正确；
- 正式伏笔是否存在后文回收。

建议记录精确率、召回率和问题严重度，但以下属于硬失败：虚构重要关系、主事件遗漏、主体/客体颠倒、当前位置错误、未来信息泄漏、伪造伏笔回收。

当前自动入口为 `semantic-audit`。它按短原文窗口读取相关标注子图，不把整章一次塞入审计模型；每个问题必须绑定标注对象或 `missing:<kind>:<证据单元ID>`。现有对象的语义问题至少要引用该对象自身证据，缺失的独立行动不能借用另一个正确事件的ID。自动结果用于生成复核队列和发布阻断证据，不能取代五章人工内容阅读。

审计驱动修复使用 `repair-annotation-cycle`。提交资格必须同时满足：基线与候选重审的章节、窗口、模型和提示词版本兼容；候选重审不含 `audit_contract`；候选内容审计通过；全部高置信修复目标被独立确认。问题总数、错误数或平均置信度单项下降只能作为诊断信号。模型重审未匹配到基线的问题标记为 `unmatched_candidate_issues`，不得未经人工确认就称为新回归。

## 4. 章节程序评测

章节程序必须覆盖原章核心事件，同时控制扩写边界。

| 指标 | 含义 |
|---|---|
| 核心事件覆盖率 | 标为核心的事件是否都分配到场景和段落 |
| 事实唯一归属率 | 每个事实是否只由一个主要段落负责实现 |
| 顺序一致率 | 事件、反应和结果是否保持正确偏序 |
| 无授权扩写率 | 新增节拍是否都具备合理推导或氛围扩写依据 |
| 篇幅可执行性 | 场景和段落预算是否足以演出规定动作 |

核心事件遗漏、未来事件进入当前章、结果早于原因，均为硬失败。

## 5. 单章正文评测

### 5.1 硬门控

- 核心事实与事件均有正文证据；
- 没有与图谱冲突的人物、关系、时空、资源和结果；
- 没有未授权的新设定、新动机、新关系或新结局；
- 所有状态变化都能生成候选图谱补丁；
- 没有泄露未来章节事实；
- 篇幅处于章节程序允许范围。

硬门控失败时正文不得发布，也不得为下一章提供状态。

### 5.2 软评分

- 场景是否真正演出，而非复述梗概；
- 动作—反应—后果是否完整；
- 信息释放是否符合场景职责；
- 对话是否改变信息、关系、目标或情绪；
- 段落节奏、叙述距离、语言密度是否符合作者策略；
- 阅读是否连贯，是否存在重复总结和无效扩写。

## 6. 跨章连续性评测

至少运行5章，候选Skill阶段运行10章，发布前运行20章。检查：

- 已提交状态矛盾数；
- 因果父事件缺失数；
- 人物位置和资源无依据跳变数；
- 人物知识提前获得数；
- 开放线索遗忘、误回收或重复回收数；
- 图谱补丁失败后仍启动下一章的次数；
- 章节目标与卷级事件链的偏移。

硬性连续性矛盾、未来泄漏和越过失败章节继续生成的次数必须为零。

## 7. 作者辨识度评测

作者辨识度至少采用三类证据：

1. **可解释统计：** 句段节奏、对话结构、叙述距离、信息释放、转场和钩子；
2. **对照判别器：** 目标作者与同题材作者的匿名文本分类或嵌入距离；
3. **盲评：** 不显示系统名称，让评审比较通用基线与作者Skill版本。

必须做以下对照实验：

| 实验 | 要回答的问题 |
|---|---|
| 无Graph-RAG vs Graph-RAG | 图谱检索是否提高连续性 |
| 通用题材提示词 vs 作者Skill | Skill是否真的增加作者辨识度 |
| 全局风格表 vs 场景条件策略 | 条件化规则是否更有效 |
| 单候选 vs 多候选重排 | 选择机制是否提高质量 |
| 单作品画像 vs 跨作品作者核心 | 是否摆脱单书特化 |

通过标准不绑定某个固定分类器阈值，但必须满足：作者Skill在多数留出任务上稳定优于通用基线，提升不能主要由题材词、来源专名或字面复写贡献。

## 8. 防复写评测

至少检查：

- 最长公共连续字符串；
- 字符 n-gram 重合；
- 近重复句比例；
- 与来源段落的向量近邻；
- 来源专名、独有设定和原剧情组合泄漏。

阈值应由开发集和正常中文相似度基线校准，保存到 `quality_thresholds.json`。超过阈值的候选直接拒绝，不能通过“风格很像”抵消。

## 9. Skill可移植性评测

在不提供编译机原文目录的环境中检查：

1. `SKILL.md` frontmatter和引用路径合法；
2. 所有清单文件存在且模式版本匹配；
3. 脚本能够完成自检和写作包组装；
4. 不含绝对路径、API密钥或来源正文；
5. 使用一份全新故事状态能够完成规划、生成、校验和补丁提交；
6. `evaluation/acceptance_report.json` 能复现所用数据版本、模型版本和基线。

## 10. 错误归因

统一错误类别：

| 错误码 | 含义 | 首选处理 |
|---|---|---|
| `annotation_gap` | 来源事件或事实未提取 | 重标对应窗口 |
| `entity_resolution` | 同指实体分裂或误合并 | 修正实体候选与全局投影 |
| `graph_semantics` | 关系、因果、时空或状态边错误 | 修图谱构建与语义复核 |
| `program_omission` | 章节程序漏掉事件或节拍 | 重编译受影响场景 |
| `retrieval_miss` | 已存在信息未进入写作包 | 调整检索种子、边和预算 |
| `draft_hallucination` | 正文生成未授权内容 | 拒绝候选并定向修复 |
| `style_deviation` | 内容正确但写法偏离 | 调整条件画像或候选重排 |
| `copy_risk` | 与来源文本过度重合 | 拒绝候选并降低来源可见性 |
| `model_capability` | 在输入正确时仍无法可靠执行 | 更换模型或增加参数适配实验 |

## 11. 发布门槛

只有同时满足以下条件，Skill状态才能从 `candidate` 升为 `validated`：

- 至少两部作品支持作者核心，并完成作品或连续章节留出；
- 5章内容级标注抽检通过；
- 核心事件实现且硬性事实矛盾为零；
- 5/10/20章连续生成门槛按阶段通过；
- 作者Skill相对通用基线在盲测中稳定提升；
- 防复写、未来泄漏和可移植性测试通过；
- 所有结论带数据、模型、提示词和评测版本。
