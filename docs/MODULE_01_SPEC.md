# 第一模块规格：章节剧情压缩

## 1. 唯一职责

第一模块把单章原文压缩为可追溯的章节剧情梗概，回答“本章发生了哪些主要推进”。
它不决定跨章层级中的必写内容，也不建立事实、实体、关系、时间线、伏笔生命周期或文风特征。

## 2. 固定流程

1. 为全章自然段建立稳定的 `P0001...Pn` 编号。
2. 全章导航按“一个主导推进或一次主要状态变化”划分连续事件单元，不设单区字符数、段落数或全章区数限制；程序只校验完整覆盖、顺序、重叠和遗漏。
3. 独立语义审校检查分区是否包含多个可分推进而过大，或只有细节而过碎；必要时只修订并复核一次。
4. 相邻完整导航块组成传输批次。批次最多 4 块、原文合计以 6000 字符为软装载目标；单个较长分区独占批次，不得为适应请求而拆区。
5. 每个分区恰好生成一条局部梗概，程序分配唯一的 `B001-S001` ID。
6. 每个传输批次只做一次局部事实风险扫描，按分区返回警告和重大疑似错误，不在局部层判断遗漏。模型只报告问题和逐字证据；程序验证候选片段、段落所有权与原文片段。无效证据降为诊断警告，普通警告允许通过，只有有效重大疑似错误进入独立裁决。
7. 只有经裁决确认的重大错误才允许在原候选上做一次最小修正；随后只验证这些已确认问题是否解决，不重新扫描遗漏或一般性改进点。程序将完整分区范围确定性绑定为该区唯一梗概的正式回查范围。
8. 章首和章末使用独立的首尾原文切片提取状态。章首严格锚定正文第一段；章末描述末尾收束片段共同形成的最终局面，最后一段只标记章节终点，不是唯一可用证据。模型核验语义，程序为章首绑定首段ID、为章末绑定整个收束切片的段落ID。
9. 章级模型只读取按原文顺序锁定的全部局部梗概，生成一段完整章节梗概；允许多个句子，不设置固定句数。
10. 章节梗概分别检查已有陈述的事实一致性和章节级主线完整性；不要求逐条复述所有局部梗概。普通警告和可选补充不阻断，只有有证据的重大错误或会改变主线、结果、章末状态理解的重大遗漏才失败。
11. 只有存在重大错误或重大遗漏时，才允许在原候选章节梗概上做一次最小修正，随后分别复核一次；程序将全部局部梗概ID按原顺序确定性绑定为来源。
12. 组装并验证 schema 5.0 正式产物。流程到此结束，不迭代。

设局部批次数为 `B`。正常逻辑请求数为 `9 + 2B`；若导航、每个局部批次和章节梗概都发生一次允许的修补，上限为 `14 + 5B`。累计输入放大率只产生统计告警，不再让已推进章节因总字符量失败。

## 3. 正式输出

```text
ChapterSynopsisBundle
  schema_version = 5.0
  chapter_id
  source_hash
  local_synopses[]
    window_id
    chapter_id
    reviewed_source_unit_ids[]
    segments[]
      segment_id
      order
      summary
      source_unit_ids[]
  chapter_synopsis
    chapter_id
    opening_state { text, source_unit_ids[] }
    chapter_summary { text, local_segment_ids[] }
    ending_state { text, source_unit_ids[] }
  quality
```

分区数量取决于原文中主导推进和主要状态变化的数量，不设总数上限；每个分区的 `segments`
必须恰有一项。章节梗概直接引用全部局部梗概ID，引用顺序必须与原文顺序完全一致。

## 4. 质量门

- 导航范围恰好覆盖全部原文段落；
- 每个分区通过粒度审校，不得包含多个可独立推进；过碎只记录诊断，不阻断也不自动合并；
- 每批局部梗概经过一次按目标隔离的事实风险扫描；其他分区和前情不得作为当前目标的事实证据；
- 警告与通过相互独立，允许 `passed=true`、`has_warnings=true`；只有经证据验证和裁决确认的重大错误触发修正；
- 章首状态由正文首段直接支持；章末状态由末尾收束切片直接支持，并且不把同一收束场景的正常概括误判为边界错位；
- 章节梗概的全部陈述忠实于局部梗概；
- 章节梗概保留章节级主线、关键转折和最终结果，不要求逐条复述所有局部细节；
- 任何层最多一次修补和一次受限复核，不形成自迭代循环；局部层不进行覆盖度审查。

内容包含较多原文细节本身不是错误。质量检测关注错误陈述、确定性升级、因果或时序错配、
遗漏主要推进以及层级引用错误，不使用针对某部作品或具体剧情预写的硬编码规则。

## 5. 明确禁止

第一模块正式产物不得包含：原子事实或命题、实体表、关系、时间线、知识图谱、跨章线程、
章节阶段、剧情功能分类、`story_change`、作者目的、文风或模板。

`source_unit_ids` 只是梗概的追溯依据，不是事实提取。导航标签只供内部检查，不进入内容生成。
`source_integrity_report.json` 只报告章节是否成功加载、来源哈希和段落数量，不扫描或评价原文字符异常。

## 6. 后续模块

第二模块聚合各章的有序局部梗概和章节梗概，形成事件、篇章、卷和全书层级，并由更高层结构反向判断下层哪些内容关键。
第三模块再根据大纲需求回查原文，提取必要事实、实体、关系和状态。
