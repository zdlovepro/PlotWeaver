# 软件需求规格（SRS）

**项目：** PlotWeaver  
**版本：** V3 基线与 V4 规划  
**目的：** 从获准处理的中文小说语料中蒸馏出可复用的小说作者 Skill；在不向正文生成器提供原文章节的前提下，尽量同时还原原章的故事事实、叙述结构与可量化文风。

## 1. 目标与非目标

### 1.1 目标

1. 将长篇小说拆为可追溯、可校验的叙事事实，而不是只生成章节摘要。
2. 建立单一事实底座 `narrative_graph.json`，表达人物、事件、场景、时间、空间、状态、因果、稳定关系与伏笔生命周期。
3. 蒸馏同时包含“写什么”和“怎样写”的 Skill：前者受图谱约束，后者由可解释且可测量的风格程序控制。
4. 以留出章节做盲测，定位生成差距究竟源自标注、图谱、章节程序、生成还是文风控制。
5. 允许后续接入本地模型和参数高效微调，但在未训练模型时也能以兼容 OpenAI 的推理服务运行。

### 1.2 非目标

- 不以逐字复写或记忆原文为目标；系统应避免大段重复原作表述。
- 不把通用修仙题材词汇、境界名称或情节母题误当作某位小说作者的独有文风。
- 不把结构质量报告“通过”视作小说质量通过；语义抽检和盲测是必需步骤。
- 不取代人工编辑对出版、版权和创作责任的判断。

## 2. 术语

| 术语 | 含义 |
|---|---|
| 原子事实 | 有原文证据范围的最小可核验陈述，例如“人物获得某物”或“人物离开某地”。 |
| 叙事图谱 | 从原子事实构建的本地 JSON 图，是生成时唯一的事实来源。 |
| 场景程序 | 将某章分解为场景、节拍和段落；每段绑定允许使用的事实与状态。 |
| 风格程序 | 对当前场景生效的可测量写法约束，例如叙述距离、句长节奏、对话比例、信息揭示方式。 |
| 图谱补丁 | 一章生成后，拟写入运行时图谱的状态变化、因果和伏笔变化；仅通过校验后提交。 |
| 伏笔线程 | 由后文可验证回应闭合的“埋设—回收”关系，不等同于任何神秘、疑问或未解释内容。 |

## 3. 角色与输入输出

| 角色 | 输入 | 输出 |
|---|---|---|
| 使用者 | 小说文本、作者标识、模型配置、章节范围 | 语料、Skill、规划、生成稿、评测报告 |
| 标注模型 | 短重叠原文窗口与严格 JSON 提示词 | 有证据的实体、事实、事件、场景、时空与状态标注 |
| 生成模型 | 段落事实子图、风格程序、篇幅预算 | 单段候选正文与候选图谱补丁 |
| 校验器 | 原文标注、图谱、候选正文、补丁 | 通过/拒绝及可归因的问题列表 |

## 4. 功能需求

### FR-01：导入与版本隔离

- 系统应从 `input/` 导入 `.txt` 小说，为作品分配稳定 `work_id`。
- `novels/` 只作为完整小说档案，不能被默认批处理入口误读。
- 每个中间产物必须记录来源哈希、模式版本、提取器版本和质量策略版本。
- 上游模式或质量规则变化后，下游产物必须失效或重建，不能静默复用旧数据。

### FR-02：高密度、证据化标注

- 长章节必须按受限长度的重叠窗口批量请求，不能整章一次送入模型。
- 每个实体、事实、事件、场景、时间关系与空间关系必须可定位到原文引文和偏移。
- 每个窗口都必须达到最低事件、事实、场景密度和证据覆盖率；不合格时只重做缺失窗口。
- 标注必须区分稳定人物关系、一次性交互、空间动作、状态槽位和线索候选。

### FR-03：语义叙事图谱

- 图谱必须合并有充分证据的同一实体，保留别名、置信度、来源与候选合并关系。
- 稳定关系仅包括亲属、师徒、组织隶属、同盟、敌对、契约、债务等可跨事件持续的关系；“见到、讥讽、抢夺”等应保持为事件动作。
- 因果边应聚合同一因果对的多条事实证据，并支持由目标、秘密、物品、承诺、伤势和关系状态延续形成的跨章因果。
- 地点状态必须区分“离开”“进入”“定居”“途经”“靠近”；禁止把“离开某地”写成当前位置为该地。

### FR-04：闭环伏笔

- 标注阶段只能建立“待验证线索”。
- 系统必须在后文检索同实体、物品、概念或因果状态的候选回应，并判断其是否真正解释、兑现或反转了前文线索。
- 只有通过证据比对的线索才升级为正式伏笔线程，记录埋设点、回收点、回收方式与置信度。
- 未找到回收点的线索必须标记为“未闭环”或“样本边界未验证”，不得作为生成器需要埋下的伏笔。

### FR-05：作者风格蒸馏

- 系统必须提取全局风格画像和按场景生效的风格程序。
- 风格特征至少覆盖：叙述视角与距离、句长/段长节奏、标点节奏、动作/对话/心理/环境比例、信息揭示顺序、对话轮次、情绪外显方式、段末钩子与转场方式。
- 风格规则必须给出支持样本数、适用场景、反例或不适用条件，以及相对同题材对照语料的区分度。
- 泛化写作建议不得作为已蒸馏的作者风格规则发布。

### FR-06：受控段落生成

- 生成前，运行时只能从图谱取得当前段落关联的子图和已提交的历史补丁。
- 不得向生成器发送整章原文、原文段落、未来章节事实或未提交的后续状态。
- 每段应有明确篇幅预算、叙事目标、允许事实、禁止泄露项和风格程序。
- 系统应支持生成多个候选，并按事实一致性、风格贴合、流畅度、重复度综合重排。

### FR-07：补丁提交与跨章校验

- 每章完成后必须生成候选图谱补丁。
- 正文事实、人物状态、时空、因果、伏笔生命周期和篇幅均通过后，补丁才能提交。
- 未提交的章节不得为下一章提供状态，也不得启动后续章节生成。

### FR-08：重建与风格评测

- 评测器可读取原章，但生成器不可读取原章。
- 必须分别输出事实覆盖、矛盾、事件/场景顺序、状态迁移、因果、伏笔闭环、风格相似、重复风险和人工抽检结果。
- 差异报告必须归因到“标注不足、图谱语义、章节程序、正文执行、风格控制或模型能力”中的至少一类。

## 5. 非功能需求

| 编号 | 要求 |
|---|---|
| NFR-01 | 所有模型结构化输出使用中文提示词、明确 JSON 架构和具体 JSON 示例。 |
| NFR-02 | 所有重要产物可追溯到章节、窗口、证据范围与上游版本。 |
| NFR-03 | 请求可断点恢复；失败只重试当前窗口/段落，不重做全书。 |
| NFR-04 | 图谱与生成运行时使用本地 JSON；可选接入数据库，但不得引入第二事实底座。 |
| NFR-05 | 运行日志不得泄漏模型密钥；配置文件与产物中不保存密钥。 |
| NFR-06 | 文风评测与事实评测独立；任一硬性事实矛盾都应使章节失败。 |

## 6. 验收标准

系统仅在以下条件全部满足时，才可称为“可用的小说作者 Skill”：

1. 随机抽取的原文章节可由标注和图谱逐条追溯，且不存在重大遗漏、错位或虚构关系。
2. 图谱中不存在把未回收线索标作正式伏笔、把一次互动标作稳定关系、把离开地点写作当前位置等语义错误。
3. 留出章节生成时，所有核心事件、状态变化和时空顺序可对齐，且没有未授权的新设定、新关系或新结局。
4. 风格判别器在“目标作者 vs 同题材对照作者”的留出集上优于随机与题材词基线；生成稿在对应场景下比无风格程序基线更接近目标风格。
5. 生成稿通过重复风险检测，不以长串复现原文换取风格分数。

## 7. 当前已实现与待实现

- **已实现基线：** 受限窗口标注、连续性处理、`narrative_graph.json`、单段子图生成、候选补丁与跨章提交门控、基础模板与风格产物、结构化回归评测。
- **优先待实现：** 标注模式版本化；关系/空间/因果语义修复；闭环伏笔线程；场景级风格程序；对照作者风格判别器；多候选重排；本地 LoRA/SFT/DPO 训练管线。
