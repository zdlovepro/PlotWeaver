# 模型、检索、微调与作者风格说明

**文档基线：** 2026-08-06
**结论：** 完整作者Skill首先是数据、知识、策略、检索和评测工程；改变模型参数是可选增强，不是必需步骤。

## 1. 模型在项目中的五种职责

| 职责 | 输入 | 输出 | 对模型强度敏感度 |
|---|---|---|---:|
| 语义标注 | 短原文窗口、已有局部上下文 | 实体、事件、状态、时空、因果 | 高 |
| 作者归因 | 多作品匿名观测、同题材对照 | 作者核心、适用条件、反例 | 高 |
| 正文生成 | 层级计划、局部图谱、作者策略 | 段落或场景候选 | 很高 |
| 语义评审 | 契约、候选正文、状态 | 错误与修复目标 | 高 |
| 向量/分类 | 匿名场景、风格特征 | 检索排序、作者区分分数 | 中等，可用专用小模型 |

确定性程序负责：切分、ID、证据偏移、模式解析、时间可见性、图遍历、状态提交、版本失效、统计指标和硬规则。模型不能代替这些程序边界。

## 2. 当前挫折与模型强度的关系

与模型高度相关：

- 判断称谓是否同指；
- 从对白提取真正的决策、承诺、信息转移和结果；
- 提取跨段因果和人物知识状态；
- 把结构计划落成自然、具体且不流水账的正文；
- 在复杂约束下保持文风和长篇连贯。

主要属于系统问题：

- 输入或输出长度设置错误；
- JSON契约与修复路由不匹配；
- 实体ID没有投影到下游；
- 未来节点或未提交状态进入写作包；
- 章节只有段落局部信息，没有卷/事件/章节合同；
- 质量报告只检查数量和字段；
- 单作品特征被错误标作作者核心。

更强模型能减少语义错误、提高正文质量，但不能修复错误的阈值、数据泄漏、检索范围和提交逻辑。项目必须保存固定回归集，量化“换模型”究竟改善了哪一层。

## 3. 四种模型使用层级

| 层级 | 是否训练参数 | 作用 | 进入条件 |
|---|---:|---|---|
| 提示词 + 契约 + RAG | 否 | 快速迭代、受控标注和生成 | 当前可用 |
| 本地或远程推理服务 | 否 | 更换计算位置、成本和隐私边界 | 接口兼容即可 |
| LoRA/QLoRA + SFT | 是 | 内化正文实现偏好，减少通用AI腔 | 数据和评测稳定后 |
| LoRA + DPO | 是 | 在多个合格候选中学习偏好 | SFT和偏好数据可靠后 |

Skill 与 LoRA 是不同产物：

```text
Skill = 作者知识 + 写作流程 + 检索 + 校验 + 评测
LoRA  = 可选的模型参数适配器
```

一个Skill可以指定推荐基础模型或适配器，但没有LoRA时也应能运行。

## 4. API与本地模型

当前Python流水线通过配置调用兼容服务。计算可以在远程API、笔记本或另一台GPU主机完成，代码不要求与模型在同一台机器，只要求网络可达。

常见本地推理方式：

| 服务 | 适用情况 | 特点 |
|---|---|---|
| Ollama | 单机快速试验 | 配置简单，适合量化模型和低并发 |
| llama.cpp | 显存受限、CPU/GPU混合 | GGUF生态成熟，偏推理 |
| vLLM | NVIDIA GPU、批量请求 | 吞吐高，适合标注和多候选 |
| SGLang | 多轮、结构化和批处理 | 可评估复杂推理服务 |

远程调用GPU主机时：

```text
笔记本上的PlotWeaver
  → HTTP/OpenAI兼容地址
  → GPU主机上的推理服务
  → JSON/文本响应
```

应优先通过局域网或安全隧道访问，不直接把未认证服务暴露到公网。`config.yaml` 只保存接口配置；密钥不得进入日志、清单和Skill。

## 5. 模型分工建议

无需让一个模型承担所有任务：

- 强中文指令模型：语义标注、作者归因、复杂正文生成；
- 较小本地模型：格式修复、低风险分类、批量候选初筛；
- 中文嵌入模型：作者策略RAG和匿名风格近邻；
- 轻量分类器：目标作者与同题材对照作者判别；
- 确定性代码：图谱过滤、补丁提交、复写检测和指标统计。

强评审模型与写作模型最好分离；至少使用不同提示词和不可见的留出原文，避免写作模型给自己打高分。

## 6. RAG在项目中的两种作用

### 6.1 故事Graph-RAG

解决“前面发生过什么、当前允许什么、状态是否连续”。检索对象是当前新故事或结构保真测试的图谱节点，不是原文段落。

当前实现以段落事实、事件和实体为种子，过滤未来和未提交节点，再扩展因果父链、同状态槽、关系和已验证历史。它能显著减少人物位置、资源、关系和因果断裂，但不能自动产生作者风格。

### 6.2 作者Skill RAG

解决“在当前场景中，该作者通常怎样安排和实现”。检索对象是匿名作者策略、适用条件、正文实现方式和负面约束。

推荐先用结构标签过滤，再用嵌入相似度重排：

```text
场景职责/事件类型/人物压力/叙事阶段
  → 结构过滤
  → 作者策略候选
  → 向量重排
  → 少量可执行规则
```

不要把所有作者规则和全部图谱一次塞进提示词。过多互相冲突的规则会降低遵循度。

## 7. LoRA与SFT

LoRA冻结基础模型大部分权重，只训练少量低秩适配参数；QLoRA在量化基础模型上进行类似训练。SFT是训练任务：给定匿名故事控制输入，学习输出目标正文。

推荐样本：

```json
{
  "input": {
    "story_level_context": "匿名阶段目标和事件链",
    "scene_program": "目标、阻碍、节拍、结果和篇幅",
    "local_graph": "当前段允许事实与已提交状态",
    "author_policy": "当前场景适用的作者策略"
  },
  "target": "来源段落正文"
}
```

推理/重建时禁止把待生成原文作为上下文；离线监督训练中，来源段落作为标签是允许的。训练、开发和测试必须按作品或连续章节块隔离。

LoRA实验必须与无适配器基线使用相同输入、解码参数和评测集。若只提高字面相似度却增加复写，视为失败。

## 8. DPO

DPO使用相同输入下的偏好对：

```text
chosen：硬门控通过、作者策略更贴合、可读性更好、无复写风险
rejected：事实仍可比较，但存在风格偏离、重复说明、节奏或连贯问题
```

不得简单把原文永远设为 `chosen`、把生成稿设为 `rejected`，否则模型可能学会复写。偏好对必须先经过图谱硬门控，并由多种评分和人工抽检共同确定。

## 9. 作者判别器

作者判别器不能只识别题材词。推荐融合：

1. 可解释统计：句段节奏、标点、对话结构、转场和信息释放；
2. 匿名字符或句法特征；
3. 场景条件化文本嵌入；
4. 目标作者与多个同题材作者的对照分类。

训练前去除专名，并按场景类型和篇幅配对。判别器只用于评测和候选重排，不应把来源段落作为生成上下文。

## 10. 防复写

每个候选至少检查：

- 最长公共连续字符串；
- 字符 n-gram；
- 近重复句；
- 向量近邻；
- 来源专名和独有剧情组合。

防复写是硬门控。作者判别分再高，也不能发布高重合候选。

## 11. 推荐技术栈

| 部分 | 可选工具 | 用途 |
|---|---|---|
| 基础模型 | `transformers` | 加载中文开源模型 |
| LoRA/QLoRA | `peft`、`bitsandbytes` | 参数高效训练 |
| SFT/DPO | `trl` | 训练器与日志 |
| 数据集 | `datasets` | 数据版本和划分 |
| 推理服务 | vLLM、SGLang、Ollama | 兼容接口与批处理 |
| 图谱检索 | 当前本地JSON图 + 可选向量索引 | 时间安全结构检索 |
| 风格判别 | 中文统计特征 + 编码器/分类器 | 作者区分和重排 |

训练依赖应放入独立 `training/` 子系统，不立即扩大主流水线依赖。训练产物记录基础模型、适配器、数据版本、随机种子和完整评测报告。

## 12. 推荐实施顺序

1. 修正语义标注、实体、事件、状态、因果和伏笔；
2. 完成多作品样本划分和题材对照；
3. 提取作者核心、作品偏移和条件化叙事策略；
4. 建立作者Skill RAG和无训练多候选重排；
5. 通过5/10/20章、跨作品和防复写验收；
6. 再决定是否开展LoRA/SFT；
7. 只有SFT和评测稳定后才尝试DPO。

## 13. 参考方向

- [DOME](https://aclanthology.org/2025.naacl-long.63/)：动态分层大纲与时序知识图谱的长篇故事生成；
- [STORYTELLER](https://aclanthology.org/2025.findings-acl.1071/)：剧情线与叙事实体知识图谱协同；
- [DOC](https://aclanthology.org/2023.acl-long.190/)：细粒度大纲控制长篇故事生成；
- [WebNovelBench](https://arxiv.org/abs/2505.14818)：中文网文生成评测；
- [Novel-Agent](https://github.com/sherrylxf/Novel-Agent)：图谱、RAG与章节流程的工程参考；
- [Long-Novel-GPT](https://github.com/MaoXiaoYuZ/Long-Novel-GPT)：大纲—章节—正文工作流参考；
- [LoRA](https://arxiv.org/abs/2106.09685)、[PEFT](https://github.com/huggingface/peft)、[TRL](https://github.com/huggingface/trl)：参数高效训练和偏好优化工具链；
- [TinyStyler](https://arxiv.org/abs/2406.15586) 与 [StyleMC](https://arxiv.org/abs/2312.17242)：少样本文风迁移和风格引导生成参考。

这些方法用于启发模块设计，不构成“照搬某个仓库即可得到好小说”的保证。最终仍以本项目冻结的留出集和验收规范为准。
