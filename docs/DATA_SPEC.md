# 数据、证据与样本划分规范

**状态：** 目标规范，按新版 00—09 模块逐步实现
**目的：** 保证作者蒸馏得到的是可验证规律，而不是单书剧情、题材词或数据泄漏

## 1. 数据分层

项目数据分为四类，权限和用途不同：

| 数据层 | 内容 | 可供标注 | 可供生成 | 可打包进Skill |
|---|---|---:|---:|---:|
| 来源语料 | 原始小说章节 | 是 | 否 | 否 |
| 梗概与证据结构 | 章纲、分层大纲、必要事实、图谱和引文范围 | 是 | 仅匿名结构 | 仅聚合规律 |
| 作者知识 | 跨作品风格、叙事策略、适用条件、对照分数 | 是 | 是 | 是 |
| 新故事运行态 | 新人物、新世界、已发生事件和已提交补丁 | 否 | 是 | 不固化进作者Skill |

来源语料和新故事运行态必须严格隔离。作者 Skill 只能提供“怎么写”，不能偷偷携带“原作接下来发生什么”。

## 2. 作品与样本清单

每位作者建立 `author_corpus_manifest.json`，至少记录：

```json
{
  "schema_version": "1.0",
  "author_id": "ExampleAuthor",
  "works": [
    {
      "work_id": "work-001",
      "source_sha256": "...",
      "chapter_count": 500,
      "sample_blocks": [
        {"start": 1, "end": 20, "role": "train", "segment": "opening"},
        {"start": 121, "end": 130, "role": "development", "segment": "middle"}
      ]
    }
  ],
  "held_out_work_ids": ["work-003"]
}
```

样本选择不能只取每部作品前若干章。应覆盖：

- 开篇建局；
- 日常与关系塑造；
- 信息发现；
- 修炼或能力推进；
- 对话冲突；
- 行动或战斗；
- 阶段转折；
- 高潮与收束。

早期迭代继续限制小批量：先修正现有20章，再按作品选取连续块；通过质量门槛后才扩大到50章或更多。扩大样本不能替代语义修复。

## 3. 训练、开发与盲测隔离

划分单位优先级如下：

1. **整部作品留出**：最能检验作者核心是否跨作品成立；
2. **连续章节块留出**：防止相邻段落和同一事件链泄漏；
3. **随机单章留出**：只可用于补充，不应成为唯一划分方式。

同一事件链、同一场景或高度相似段落不得跨训练集与盲测集。任何用于调提示词、阈值或人工选择的样本都属于开发集，不再算盲测。

## 4. 语义结构的产生顺序

语义结构不是在第一模块一次性无差别提取。第一模块只产出中等粒度局部剧情段、
完整章节梗概和首末边界；第二模块聚合事件与跨章大纲；第三模块才根据大纲节点的实际需要提取实体称呼、
事实、状态、时空和因果证据；第四模块负责全局合并。以下字段是第三、第四模块
完成后的标准语义结构。

## 5. 标准语义结构

每章的标准语义层至少包含：

### 5.1 实体

- 局部实体ID与全局实体ID；
- 实体类型、规范名、别名和称谓；
- 同指证据、冲突证据、合并置信度；
- 无法确认时保存候选合并，不强行合并。

### 5.2 必要事实

- 主体、谓词、客体或值；
- 极性和状态槽；
- 生效范围和失效条件；
- 服务的大纲节点和事实需求；
- 所属事件；
- 精确证据范围。

### 5.3 事件

- 行动者、承受者和其他参与者；
- 动作类型与动作内容；
- 前置条件、触发原因、目标；
- 直接结果、代价和后续义务；
- 所在场景及顺序；
- 因果父事件和因果子事件。

“说了一句话”不能自动替代话语实际产生的决策、承诺、拒绝、威胁或信息转移。模型给出的事件类型必须经过语义校验，而不仅是枚举值合法。

### 5.4 人物状态

至少支持：

- 位置；
- 身体与伤势；
- 能力、境界或技能；
- 物品和资源；
- 当前目标与承诺；
- 情绪及其来源；
- 与其他人物的稳定关系；
- 知识状态：知道、不知道、误解、怀疑和保密。

每次状态变化必须说明 `before`、`operation`、`after` 和证据。跨章运行时只读取已提交的 `after`。

### 5.5 时间和空间

- 时间使用偏序关系，不依赖字符串ID排序；
- 区分之前、之后、同时、包含和持续；
- 空间区分进入、离开、经过、靠近、居住和远程作用；
- “离开某地”只能清除或转移当前位置，不能把该地点重新写为当前位置。

### 5.6 线索与伏笔

首次出现时统一标记为 `cue_candidate`。在后文搜索回应后，状态可变为：

| 状态 | 含义 |
|---|---|
| `false_candidate` | 只是气氛、普通疑问或无后续意义的细节 |
| `open_thread` | 有持续叙事义务，但尚未证明属于伏笔 |
| `boundary_unverified` | 样本截止，无法判断后文是否回应 |
| `foreshadow_confirmed` | 后文明确解释、兑现或反转前文线索 |
| `resolved` | 已记录实际回收事件、方式和结果 |

没有后文对应不得标记为正式伏笔；生成器也不得被要求机械复现来源作品中未闭环的“坑”。

## 6. 作者特征观测

作者特征必须按“章节—场景—段落”记录原始观测，再聚合为规则。观测至少覆盖：

- 叙述视角、叙述距离和感知中心；
- 句法、句长、段长和标点节奏；
- 动作、对话、心理、环境、说明和总结的比例；
- 对话轮次、话语功能、潜台词和权力变化；
- 场景进入、退出、转场和段末钩子；
- 信息首次出现、延迟解释、误导和揭示；
- 冲突升级、选择、代价、反应和余波；
- 事件线切换、人物成长和资源积累方式。

每条聚合规则必须保存：支持作品、支持章节、场景条件、反例、稳定度、对照区分度、置信度和提取器版本。

## 7. 对照语料

同题材对照语料只用于判断某个特征是否具有作者辨识度。对照流程应：

1. 去除角色、地点、功法、组织等专名；
2. 控制场景类型和大致篇幅；
3. 计算目标作者内部稳定度；
4. 计算目标作者与同题材其他作者的差异；
5. 淘汰只识别题材词、世界设定或某部作品剧情的特征。

对照作者的原文同样不得进入最终目标作者 Skill。

## 8. 证据和版本

当前内容级语义审计产物至少包含：选中章节、短窗口、完整已核实体/事实/事件ID、问题类别、严重度、对象ID、证据单元ID、诊断、建议动作、置信度、模型和提示词版本。审计检查点指纹必须同时包含来源哈希和当前标注子图哈希；只按原文哈希缓存会在标注更新后复用过时结论，属于无效实现。

语义修复产物必须区分：正式标注、候选标注、模型补丁原载荷、确定性应用摘要、候选重审和前后验证。验证报告至少记录候选文件哈希、同尺度兼容性、每个原问题的 `deferred/still_present/structurally_resolved/not_reobserved_needs_review` 状态、阻断原因和 `eligible_for_commit`。候选产物不得伪装成正式语料进入连续性、图谱、模板或Skill编译。

审计只接受2.2及以上显式事件语义框架。旧标注在内存中推导的默认行动者不能冒充模型明确抽取结果。

每个可复用产物应具备以下信封：

```json
{
  "schema_version": "...",
  "extractor_version": "...",
  "quality_policy_version": "...",
  "source_sha256": "...",
  "model_id": "...",
  "prompt_version": "...",
  "created_at": "...",
  "payload": {}
}
```

任一关键版本或来源哈希不匹配时，下游产物必须失效。旧产物先归档，再生成新版本；不得把不同契约的JSON静默拼接。

## 9. 隐私、密钥与来源文本

- `config.yaml` 中的密钥不得写入日志、清单或Skill；
- 原始文本只保存在输入、语料快照和受控评测环境；
- 写作请求不得包含待重建原文；
- 评测器可以读取留出原文，但其输出只保存指标、短证据定位和问题归因；
- Skill 中不得保存能按顺序还原来源章节的细粒度事实全集。

## 10. 数据质量门槛

进入作者蒸馏前，样本必须满足：

1. 随机抽取至少5章完成内容级复核，而不是只看数量统计；
2. 核心实体不存在已知但未处理的高置信同指分裂；
3. 事件行动者、动作、结果和证据可对应；
4. 时间、空间和人物状态不存在硬矛盾；
5. 伏笔只包含有后文回收证据的线程；
6. 样本划分和来源哈希已冻结。

未通过的数据可以用于调试提取器，但不能进入正式作者核心或训练集。
