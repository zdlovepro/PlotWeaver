# 第一模块：章节剧情压缩

输入为 `ChapterDocument`，输出为 `ChapterSynopsisBundle 5.0`。

活动流程固定为：

1. 全章导航按一个主导推进或一次主要状态变化划分事件单元，不设尺寸或总数限制；
2. 程序确定性校验完整覆盖和顺序，独立语义审校检查分区是否过大、过碎或边界错误；过碎只记录诊断，不阻断也不合并；
3. 相邻完整块组成最多 4 块、约 6000 原文字符的软目标传输批次，绝不拆分完整分区；
4. 每个分区恰好生成一条局部梗概，程序分配 ID；
5. 每批只做一次局部事实风险扫描，不在局部层检查遗漏；警告不阻断，疑似重大错误必须引用当前分区逐字证据并经过一次独立裁决；缺失或为 `null` 的空问题数组、单对象代替单元素数组以及按目标 ID 可恢复的乱序由程序规范化并留痕，目标缺失、重复、未知或不可解释的字段类型仍然失败；
6. 只有裁决成立的重大错误才最小修补一次，随后只验证这些问题是否解决，不重新开放式扫描；
7. 章首锚定正文第一段；章末概括末尾收束片段共同形成的最终局面；边界审查的警告不阻断，无效证据由程序驳回；
8. 章级模型直接依据全部有序局部梗概生成一段允许多句的完整章节梗概，不再增加节点分组层；
9. 章节梗概分别检查已有陈述的事实一致性和章节主线完整性，只有有证据的重大错误或重大遗漏才触发一次修订；
10. 模型只报告问题与证据，`passed` 和 `has_warnings` 均由程序计算，允许带警告通过；
11. 程序把全部局部梗概ID按原顺序绑定给章节梗概，组装正式产物后结束，不循环迭代。

本模块不输出剧情功能、story change、章节阶段、跨章未决线程、事实、实体、关系、时间线、图谱、
文风或模板。导航标签不作为内容输入；段落 ID 仅用于追溯。生产流程没有跳过语义审校的开关。
独立模型能力测试应放入 `experiments/`。

所有提示词位于 `prompts/templates/`，Python 构建器只负责注入动态 JSON；模板内容哈希自动成为提示词版本。
